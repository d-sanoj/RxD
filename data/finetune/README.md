# RxD fine-tuning dataset (dataset card)

**Purpose.** Teach a small language model to answer RxD's kidney-dosing questions in our exact JSON format, applying the dose rule it is given and citing only the sources in front of it. Facts come from the RAG store and the rules engine; fine-tuning only improves format, consistency and citation habits.

**Status in the POC.** The POC runs on retrieval (RAG) and a rules engine without fine-tuning. This dataset is ready for the next step and is included so we can show how fine-tuning would work.

## At a glance

| Item | Value |
|---|---|
| Examples | 124 (train 94, valid 13, test 17) |
| Patients | 30 synthetic adults; split by patient, so no patient appears in two splits |
| Drugs | levofloxacin 28, metformin 25, gabapentin 21, nitrofurantoin 18, famotidine 14, sitagliptin 12, apixaban 6 (not in sources: teaches refusal) |
| Expected actions | adjust_dose 51, continue 27, avoid 24, insufficient_information 19, caution 3 |
| Kidney range | normal function to hemodialysis; includes stale labs and missing weight |
| Format | OpenAI-style chat JSONL: `{"messages": [system, user, assistant]}` |
| Demo patient | P001 Maria Lopez (synthetic): eGFR 26.1, CrCl 24.1, in the test split |

## What each example contains

- **system**: the RxD master prompt (`data/prompts/master_prompt.txt`), the same one the app uses.
- **user**:
  - PATIENT: demographics, conditions, medications, allergies, and the **visit intake** (symptoms and reason for the visit)
  - KIDNEY: CrCl, eGFR, stage, lab age, dialysis status, flags
  - RULE: the label rule for this kidney function
  - SOURCES: label chunks plus the patient's intake chunk, each with a chunk_id
  - QUESTION: the clinician's question
- **assistant**: the correct JSON answer: action, dose, maximum, the kidney measure used, a rationale of 80 words or fewer, monitoring, citations and confidence.

## How the answers were made

The answers were **generated by code, not written by hand or by an AI**. `tools/generate_dataset.py` applies the renal dosing rules taken word for word from FDA labels (openFDA, retrieved 21 November 2026):
- metformin and sitagliptin by eGFR
- gabapentin, nitrofurantoin, levofloxacin and famotidine by creatinine clearance

Data-quality rules come first:
- a creatinine more than 90 days old gives `insufficient_information`
- missing weight blocks the creatinine-clearance drugs, but not the eGFR drugs
- for nitrofurantoin with missing weight, an elevated creatinine still gives `avoid`, per the label

Re-running the script reproduces the same files exactly (fixed random seed).

**Validation:** all 124 answers are valid JSON; 0 citations point to a source that is not in the prompt; every rationale is 80 words or fewer.

## How it would be used

Use LoRA on a small model such as Qwen2.5 1.5B or Llama 3.2 1B, for 2–3 epochs. On a laptop GPU or Apple Silicon this takes minutes. To evaluate, compare action accuracy, JSON validity and citation validity on the test split, base model versus tuned model.

## Limits and ethics

- All patients are synthetic.
- The rules cover 6 drugs and one product label each; a pharmacist must verify every rule before any real use.
- Fine-tuning never replaces the rules engine or clinician approval.
- The dataset is small by design, for a proof of concept.
